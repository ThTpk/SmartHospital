Theory · Workflow & Queue analysis

ทฤษฎีการวิเคราะห์ workflow และแถวคอย
ต้องเก็บข้อมูลอะไร นำไปวิเคราะห์อย่างไร และได้คำตอบอะไร

ใช้ได้กับทุกระบบที่มีผู้รับบริการมารอรับบริการ เช่น โรงพยาบาล ธนาคาร ศูนย์บริการ ร้านอาหาร หรือ call center ตัวอย่างในหน้านี้ใช้ค่าจริงจากแบบจำลองโรงพยาบาลของระบบนี้

01พื้นฐาน: workflow กับ queue

Workflow analysis ตอบว่าผู้รับบริการเดินผ่านหน่วยใดบ้าง เรียงลำดับอย่างไร และมีจุดส่งต่อกี่จุด Queue analysis ตอบว่าในแต่ละหน่วยผู้รับบริการต้องรอนานเท่าไร เพราะอะไร และต้องปรับอะไร ทุกจุดส่งต่อใน workflow คือคิวใหม่หนึ่งคิว ดังนั้นต้องวิเคราะห์ทั้งสองอย่างร่วมกัน

แถวคอยหนึ่งหน่วยอธิบายด้วยสัญลักษณ์ของ Kendall

A / S / c / K / N / D

ความหมาย

สัญลักษณ์ Kendall

  • A รูปแบบการมาถึง (M = Poisson, G = ทั่วไป)
  • S การกระจายของเวลาให้บริการ (M = exponential, D = คงที่, G = ทั่วไป)
  • c จำนวนช่องบริการ (service slot)
  • K ความจุของคิว · N ขนาดประชากร · D กฎการเรียก (FIFO, priority)

พารามิเตอร์หลัก

3 ค่าที่ต้องรู้

  • λ อัตรามาถึง (ราย/ชม.)
  • μ อัตราให้บริการต่อ slot = 1 ÷ เวลาให้บริการเฉลี่ย
  • c จำนวน slot ที่เปิดจริง
  • ได้ ρ = λ ÷ (c·μ) ซึ่งต้องน้อยกว่า 1

กฎที่ใช้ได้เสมอ

Little's law

  • L = λ · W
  • จำนวนคนในระบบ = อัตรามาถึง × เวลาที่อยู่ในระบบ
  • ใช้ได้โดยไม่ต้องสมมติการกระจาย จึงใช้ตรวจข้อมูลจริงได้

05การวิเคราะห์แต่ละแบบทำอย่างไร

แต่ละการวิเคราะห์ระบุวิธีทำ สูตร และผลที่ได้ ส่วนรหัส A1–A12 ใช้อ้างอิงในตารางผลลัพธ์ข้อ 06

A1

ค้นหา workflow จริง (Process mining)

นำ event log มาจัดกลุ่มตาม case_id เรียงตามเวลา จะได้ลำดับหน่วยที่ผู้ป่วยแต่ละคนผ่าน นับรูปแบบเส้นทาง (variant) ที่พบบ่อย แล้วคำนวณความน่าจะเป็นที่ผู้ป่วยไปต่อจากหน่วย i ไปหน่วย j

pij = จำนวนครั้ง i→j ÷ จำนวนครั้งที่ออกจาก i

ผลที่ได้: แผนผัง workflow (เช่น swimlane), เส้นทางของแต่ละ process, จำนวนครั้งที่ผู้ป่วยกลับมาหน่วยเดิม (เช่น พบแพทย์รอบฟังผล)

A2

วิเคราะห์การมาถึง (Arrival)

นับจำนวน ① ในแต่ละชั่วโมงของแต่ละหน่วย หาค่าเฉลี่ยรายชั่วโมงของแต่ละวันในสัปดาห์ แล้วตรวจว่าการมาถึงเป็นแบบสุ่ม (Poisson) หรือไม่ จากระยะห่างระหว่างผู้มาถึง

λ = จำนวนผู้มาถึง ÷ ชั่วโมง ; ถ้า SD ของ inter-arrival ≈ ค่าเฉลี่ย (CV ≈ 1) → Poisson

ผลที่ได้: λ(t) รายชั่วโมง, ชั่วโมงพีค, ความผันผวนรายวัน

A3

วิเคราะห์เวลาให้บริการ (Service time)

คำนวณ S = ③ − ② ของทุกราย หาค่าเฉลี่ย ส่วนเบี่ยงเบนมาตรฐาน และเปอร์เซ็นไทล์ แยกตามประเภทงานหรือผู้ให้บริการ เพื่อดูว่าความแปรปรวนมาจากไหน

μ = 1 ÷ S̄ ; CV² = Var(S) ÷ S̄²

ผลที่ได้: service time เฉลี่ย, ความแปรปรวน (เลือกแบบจำลอง M/M/c หรือ M/G/c), หน่วยที่เวลาไม่สม่ำเสมอ

A4

ความสามารถรองรับและ utilization

เทียบภาระที่เข้ามากับความสามารถของหน่วย ถ้า ρ ≥ 1 แปลว่ารับไม่ไหว คิวจะยาวขึ้นเรื่อย ๆ หน่วยที่ ρ สูงที่สุดคือคอขวด

capacity = c × 60 ÷ S̄ (ราย/ชม.) ; ρ = λ ÷ (c·μ)

ผลที่ได้: คอขวดของระบบ, หน่วยที่ใช้ทรัพยากรน้อยเกินไป (ρ < 50%)

A5

เวลารอและความยาวคิว (M/M/c)

ใช้สูตร Erlang-C หาความน่าจะเป็นที่ผู้ป่วยต้องรอ แล้วคำนวณความยาวคิวและเวลารอเฉลี่ย ถ้าเวลาให้บริการไม่ใช่ exponential ให้คูณด้วย (1 + CV²) / 2

Lq = Pwait·ρ/(1−ρ) ; Wq = Lq/λ ; W = Wq + S̄

ผลที่ได้: เวลารอเฉลี่ย, จำนวนคนรอเฉลี่ย, เวลาอยู่ในหน่วยทั้งหมด

A6

ค่าสูงสุดที่ควรเตรียมรับ (percentile)

ค่าเฉลี่ยไม่พอสำหรับวางแผนพื้นที่ จึงหาค่าที่ 95% ของเวลาจะไม่เกิน ใช้กำหนดจำนวนเก้าอี้รอและเป้าเวลารอ

P(Nq ≥ n) = Pwait·ρn ; P(Wq > t) = Pwait·e−(cμ−λ)t

ผลที่ได้: คิวสูงสุด (P95), เวลารอสูงสุด (P95), จำนวนเก้าอี้ ≈ คิว P95 × 1.5 (รวมญาติ)

A7

โครงข่ายคิวและเวลารวมของแต่ละ process

แต่ละหน่วยรับผู้ป่วยจากหลาย process รวมกัน จึงต้องคำนวณ λ ของแต่ละหน่วยจากเส้นทาง แล้วรวมเวลาของทุกหน่วยตามเส้นทาง ถ้าหน่วยต้นทางรับไม่ไหว หน่วยปลายทางจะได้รับผู้ป่วยน้อยลง

λj = λ0j + Σi λi·pij ; เวลารวม = Σ W ตามเส้นทาง

ผลที่ได้: เวลาที่ผู้ป่วยแต่ละ process อยู่ในโรงพยาบาล, process ที่สร้างภาระให้คอขวดมากที่สุด

A8

สภาวะล้นระบบ (ρ ≥ 1)

สูตรสภาวะคงตัวใช้ไม่ได้เมื่อ ρ ≥ 1 จึงใช้การประมาณแบบของไหล (fluid) คิวจะเพิ่มขึ้นในอัตราที่ผู้มาเกินกำลังบริการตลอดช่วงเปิดให้บริการ

คิว ณ เวลา T ≈ (λ − cμ) × T ; รอของคนสุดท้าย ≈ คิว ÷ (cμ)

ผลที่ได้: แถวคอยสูงสุดเมื่อแก้ไขไม่ได้, เวลาที่ต้องเปิดบริการเกินเวลา

A9

หาจำนวน slot และทางเลือกปรับปรุง (what-if)

ทดลองเพิ่ม c ทีละ 1 จนกว่า Wq ≤ เป้าหมาย และ ρ ≤ 85% ถ้าเกินขีดจำกัดพื้นที่ ให้หา service time ที่ต้องลดลง หรือจำนวนผู้ป่วยที่ต้องย้ายไปช่วงอื่น

c ขั้นต่ำ ; กฎรากที่สอง c ≈ a + β√a (a = λ/μ) ; λmax = 0.85·c·μ

ผลที่ได้: จำนวน slot ที่ต้องเปิด, เป้าลดเวลาให้บริการ, จำนวนนัดที่ต้องกระจาย

A10

แบ่งช่วงเวลา (time-varying / SIPP)

ผู้ป่วยมาไม่เท่ากันทั้งวัน จึงแบ่งวันเป็นช่วงละ 1 ชั่วโมง ใช้ λ(t) และ c(t) ของแต่ละช่วงคำนวณแยกกัน แล้วจัดเวรให้ตรงกับช่วงพีค

คำนวณ M/M/c แยกทุกช่วง t ด้วย λ(t), c(t)

ผลที่ได้: ตารางเวรรายชั่วโมง, ชั่วโมงที่ต้องเปิดช่องเพิ่ม

A11

ตรวจสอบแบบจำลอง (Validation)

เทียบ Wq ที่วัดได้จริง (② − ①) กับค่าจากแบบจำลอง และตรวจ Little's law จากข้อมูลจริง ถ้าต่างกันมาก ให้กลับไปตรวจข้อมูลหรือสมมติฐาน เช่น มีผู้ป่วยแซงคิวหรือเปิดช่องไม่ครบ

L = λ·W ; ความคลาดเคลื่อน = |Wq จริง − Wq แบบจำลอง| ÷ Wq จริง

ผลที่ได้: ความเชื่อมั่นว่าแบบจำลองใช้ทำนายได้

A12

จำลองเหตุการณ์ไม่ต่อเนื่อง (DES)

เมื่อระบบมีเงื่อนไขที่สูตรรองรับไม่ได้ เช่น คิวตามลำดับความสำคัญ ผู้ป่วยละทิ้งคิว หรือเปลี่ยนจำนวน slot ระหว่างวัน ให้จำลองผู้ป่วยทีละรายด้วยตัวเลขสุ่ม แล้ววัดผลแบบเดียวกับข้อมูลจริง

สุ่ม inter-arrival ~ Exp(λ), S ~ การกระจายที่วัดได้ แล้ววัดผลซ้ำหลายรอบ

ผลที่ได้: ผลที่สมจริงขึ้นและภาพเคลื่อนไหว (แท็บจำลอง 3D ของระบบนี้)

06ผลลัพธ์ที่การวิเคราะห์คิวหาคำตอบให้ได้

คำถามที่การวิเคราะห์ตอบได้การวิเคราะห์วิธีหาคำตอบตัวอย่างจากระบบนี้
หน่วยไหนเป็นคอขวดA4หน่วยที่ ρ สูงสุด หรือ ρ ≥ 1ก่อนปรับ: ห้องยา ρ 110% (รับได้ 55 ราย/ชม. แต่มี 61 ราย/ชม.)
ผู้ป่วยต้องรอนานแค่ไหน (เฉลี่ยและกรณีแย่)A5 A6Wq เฉลี่ย และ Wq P95ห้องยาหลังปรับ: เฉลี่ย 3 นาที, 95% รอไม่เกิน 13 นาที
คิวยาวที่สุดกี่คน ต้องมีเก้าอี้กี่ตัวA6คิว P95 × 1.5ห้องยา: คิว P95 = 15 คน → เก้าอี้ ≈ 23 ตัว
ต้องเปิดกี่ช่องบริการA9 A10c ขั้นต่ำที่ทำให้ Wq ≤ เป้า และ ρ ≤ 85%X-ray: 3 → 4 เครื่อง (รอ 24 → 3 นาที)
ถ้าเพิ่ม slot ไม่ได้ ต้องลดเวลาให้บริการเท่าไรA9หา S ที่ผ่านเป้าด้วย c สูงสุดห้องยา: 6.5 → 5.8 นาที (−11%) ร่วมกับ 7 ช่อง
รับผู้ป่วยได้สูงสุดกี่รายต่อชั่วโมงA4 A9λmax = ρmax × c × μห้องยา 7 ช่อง: ≈ 61.6 ราย/ชม. ที่ ρ 85%
ถ้าไม่แก้ไข คิวสิ้นวันเท่าไรA8(λ − cμ) × ชั่วโมงเปิดห้องยาก่อนปรับ: +5.6 คน/ชม. → ≈ 45 คนเมื่อครบ 8 ชม.
ผู้ป่วยแต่ละ process อยู่ในโรงพยาบาลนานเท่าไรA7Σ W ตามเส้นทางตรวจโรค + เอกซเรย์: 1 ชม. 29 นาที → 58 นาที
การลดความแปรปรวนช่วยได้แค่ไหนA3 A5Wq × (1 + CV²)/2ห้องยา: เวลาจ่ายยาคงที่ (CV² = 0) รอ 3.0 → 1.5 นาที
ช่วงเวลาไหนต้องเพิ่มเจ้าหน้าที่A2 A10ρ(t) รายชั่วโมงใช้ λ รายชั่วโมงจากข้อมูลจริง (ระบบนี้ใช้ค่าเฉลี่ยทั้งวัน)
หน่วยไหนมีทรัพยากรเกินจำเป็นA4ρ < 50% ต่อเนื่องPACU ρ 25% → ย้ายพยาบาลไปช่วยหน่วยอื่นได้
แบบจำลองเชื่อถือได้หรือไม่A11เทียบ Wq จริงกับแบบจำลองระบบนี้เทียบสูตรกับ DES ในคอลัมน์ DES ของตาราง

07ข้อควรระวังและสมมติฐาน

  • ภาระเปลี่ยนตามเวลา — ค่าเฉลี่ยทั้งวันซ่อนชั่วโมงพีค ควรวิเคราะห์รายชั่วโมง (A10)
  • การมาถึงไม่สุ่ม — ผู้ป่วยนัดมาตรงเวลา ทำให้ CV ของการมาถึงต่ำกว่า 1 และสูตร Poisson จะประเมินเวลารอสูงเกินจริง
  • ลำดับความสำคัญ — ER ใช้ ESI ไม่ใช่มาก่อนได้ก่อน ควรแยกคิวตามระดับหรือใช้ DES
  • ละทิ้งคิว / กลับก่อน — ถ้ามีผู้ป่วยกลับก่อนมาก เวลารอที่วัดได้จะต่ำกว่าความต้องการจริง ต้องเก็บ ④
  • ข้อมูลไม่ครบ — timestamp ที่บันทึกย้อนหลังหรือกดพร้อมกันหลายราย ทำให้ S ผิด ต้องตรวจในขั้นเตรียมข้อมูล
  • ขนาดตัวอย่าง — ควรมีอย่างน้อย 100–200 รายต่อหน่วยต่อช่วงเวลา และเก็บ 2–4 สัปดาห์ให้ครอบคลุมทุกวันในสัปดาห์
  • ความเป็นส่วนตัว — แปลง HN เป็นรหัสนิรนามก่อนวิเคราะห์ และเก็บเฉพาะข้อมูลที่จำเป็นตาม PDPA
